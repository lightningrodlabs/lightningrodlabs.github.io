    WebRTC without a signaling server

    WebRTC is supposed to be peer-to-peer. In practice, it is not. Almost every WebRTC call today depends on servers that someone has to run, and the libraries that support WebRTC carry that centralized assumption into their design.

    This post is about pulling WebRTC back toward peer-to-peer, starting with the signaling server. @lightningrodlabs/webrtc-peer gives a peer-to-peer app a managed WebRTC connection per peer, over whatever channel it already has. It ends with the plan for large calls with no server at all.

    Moving the Moss tools to Holochain 0.7

    Over the past couple of weeks we upgraded all fifteen Lightningrod Labs tools in Moss to Holochain 0.7, and every one of them is now in the Moss 0.16 tool library: Notebooks, Emergence, KanDo, Talking Stickies, Gamez, Who's In, Spreadsheets, Converge, DataTub, Glass Bead Game, Files, Vines, FarmHack, Slate and Acorn.

    The practical bit first. 0.7 is a new network, so the 0.7 version of a tool can't see anyone still on the 0.6 version, and your group should upgrade together. Most of the tools have an export/import so you can bring your stuff along; each tool's changelog in Moss says how.
