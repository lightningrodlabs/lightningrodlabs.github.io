    Moving the Moss tools to Holochain 0.7

    Eric Harris-Braun · September 14, 2026

    Over the past couple of weeks we moved nearly all of the Lightningrod Labs tools in Moss over to Holochain 0.7. Thirteen of them are now in the Moss 0.16 tool library: Notebooks, Emergence, Kando, Talking Stickies, Gamez, Who's In, Spreadsheets, Converge, DataTub, Glass Bead Game, Files, Vines and Farmhack. Slate is close behind.

    The practical bit first. 0.7 is a new network, so the 0.7 version of a tool can't see anyone still on the 0.6 version, and your group should upgrade together. Most of the tools have an export/import so you can bring your stuff along; each tool's changelog in Moss says how. Nothing on the Moss 0.15 side has changed, so nobody gets stranded before they choose to move.

    Upgrades are usually a slog, and parts of this one were. But a few things came out of it that I found really interesting, and one that I'm just plain happy about: Spreadsheets and Slate are finally going to be really usable. So here's the story.

    The bytes are the agreement

    Here's something about Holochain that I think is still under-appreciated. A DNA isn't just code running on a server somewhere. It's the rule-set a group of peers has agreed to play by, and its hash is its identity. Change a single byte of the compiled wasm and you have a different DNA, which means a different network, which means everyone who installed the old one is now alone in a room nobody else can get into.

    That makes "we didn't touch the DNA" a surprisingly slippery claim. Wasm builds aren't reproducible by default, since absolute file paths end up in the debug sections. And at one point we added a comment to an integrity zome in Emergence, just a comment, and the hash moved, because Holochain's error macro bakes line numbers into the binary.

    So rather than trusting ourselves not to rebuild, we made rebuilding impossible. Each tool's happ is now built once, stripped down with wasm-opt, and published as its own release with its hash recorded in the repo. Every UI release after that downloads that exact frozen happ, and CI refuses to publish if the hash inside the package doesn't match. That's the difference between discipline and structure, and I'll take structure every time. Every happ on the 0.16 list is byte-for-byte what we froze, and we can ship UI fixes whenever we like without any risk of splitting a group.

    The same logic is why we didn't wait for Holochain 0.7.1. We diffed the HDK and HDI crates against the release candidate and the only changes were version pins. The breaking changes are on the conductor side, and Moss ships the conductor, not us. Rebuilding our zomes against 0.7.1 would have forked every network for no benefit at all, so the 0.7 line of these tools stays pinned to exactly 0.7.0.

    Syn as glue

    When Will and I first sketched out Syn, the idea was a general pattern for real-time collaboration on Holochain. Working through this upgrade made it clearer to me what that pattern really is: glue between two layers of mature technology. Underneath is Automerge, a CRDT library that people have spent years getting right, which handles merging everyone's concurrent changes into one shared document. On top is a good UI that already knows what its data means. Syn sits in between. It keeps the Automerge document in sync over Holochain, runs the sessions, and records the commits. You don't write merge logic and you don't write sync; you describe your state and the changes to it, and you build the interface.

    That's what makes tools so easy to build this way. Kando and Talking Stickies are our own home-grown UIs on exactly this pattern. It also means you can take a full-featured editor, not a toy, and make it collaborative peer-to-peer. Spreadsheets does this with Univer, a complete spreadsheet engine, and Slate does it with Excalidraw, the whiteboard lots of you already know. Both have been in Moss for a while, and honestly, both have been fragile. Getting them to really work well is the part of this upgrade I'm proudest of.

    The lesson from making them work: lean on both layers, and don't invent anything in between. The people who built these editors already thought hard about collaboration, and they left the hooks in. Excalidraw stamps every element with a version number and a random nonce, and its own collaboration code settles every conflict with one rule: the higher version wins, and on a tie the lower nonce wins. Univer expresses every change as a small mutation that it knows how to replay from a collaborator. So Automerge does the merging, the editor decides what a change means, and Syn just carries it between peers.

    Slate used to get this wrong in a very understandable way. It stopped listening to remote changes while you were drawing, then saved the whole scene when you finished, so if someone moved a shape while you were mid-stroke, your save could quietly put it back. Now it applies Excalidraw's own version rule in both directions, and merges into the shared document property by property, so if you recolor a box while I'm moving it, we both get our way. A freehand stroke appends only its new points instead of rewriting the whole line every time it saves. And it all runs on Excalidraw 0.18 now.

    Spreadsheets got the current Univer engine, four releases newer. Univer treats those as breaking changes, but when we diffed the packages, the saved workbook format hadn't changed at all, so old boards open just fine. Then came my favorite bug of the whole upgrade. If you added a sheet, everyone else saw it, but it vanished from your own screen. Delete one sheet and every sheet except the first disappeared. Reload, and everything was back.

    That last part was the tell. The shared log of changes had been complete and correct the whole time; only your local view was wrong. A reconciler was comparing the live workbook against the board's original creation snapshot, which never gets updated, and "fixing" the difference by deleting whatever wasn't there on day one.

    Once that was fixed, undo started working too, and in just the way you'd want in a collaborative tool. Both editors keep undo local to each person, and in both, changes arriving from your peers never land on your undo stack. In Spreadsheets that falls out of how peer changes are replayed; in Slate we tell Excalidraw so explicitly. Either way, undo only ever undoes your own edits, which is exactly right when five people are in the same document. This is what I love about building on an agent-centric foundation: each agent's perspective stays its own, and the merging happens where it should.

    The catch with collaborative software is that its bugs only show up when more than one person is using it, and clicking around in three windows at once only gets you so far. So for Slate we're building a harness that drives three real agents (three conductors, three browsers) through edits to different shapes, simultaneous edits to the same shape, and long soak runs, and checks that everyone ends up with the same drawing. When that says Slate is ready, it ships.

    Working with agents

    I should also say how this got done, because it has changed how I work. I wrote a plan with a standard recipe for each tool, Claude agents did most of the porting, and separate agents reviewed that work. My part was what they can't do: open each tool in Moss as two users, click around, and decide whether it was ready to publish. Most of the bugs above turned up in those walkthroughs.

    The agents were fast and mostly very good, and they were also wrong in instructive ways. One reported CI as green after checking only the release workflow, while the test workflow on two repos had been red the whole time because an old Nix couldn't evaluate the new toolchain. Another agent's "passing" test log turned out to contain a crash that never used the word "error". What worked was requiring every claim to come with evidence, and having another agent go check it. That isn't so different from how I'd want a human team to work either.

    Everything we learned about the upgrade itself went into an upgrade-holochain-0.7 skill in holochain/ai-tools, so the next person (or agent) doesn't have to learn it all again.

    What's next

    Slate, then moving the Tauri and Android builds of Vines, Emergence and Kando onto our own tauri-plugin-holochain. And a big thanks to Damien (ddd-mtl), whose libraries Files and Vines are built on, for letting us finish and publish their 0.7 ports.

    See you in Moss!

    P.S. For the technically inclined: the frozen-happ release scripts are in each tool's repo (start with RELEASE.md in notebooks), Slate's Excalidraw merge is in ui/src/elementSync.ts in slate, and the skill covers the gotchas that cost us the most time, like npm caret ranges on 0.x versions, two git tags of one repo quietly putting two copies of a crate in your DNA, and the Rust 1.91 floor for the 0.7 crates.
